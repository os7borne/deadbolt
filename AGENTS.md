# Deadbolt — agent guide

A private password and passkey manager for one person's devices: **iPhone 11 (iOS), MacBook Air M2 (macOS), Chrome on Mac**. Autofill, save new passwords, passkeys, end-to-end encrypted sync. **No server ever holds readable data or a full vault.**

This file is the source of truth for decisions, structure and plan. Update it when a decision changes; don't re-litigate settled ones without the owner.

---

## 1. Settled decisions

| Area | Decision |
|---|---|
| Name / location | Deadbolt, `custom-ext/deadbolt/` |
| Min OS | iOS 18+, macOS 15+ (both devices run iOS 26 / macOS 26) |
| Apple code | Native Swift + SwiftUI. Project generated by **xcodegen** (`project.yml`), like `../sugar`. Team `4CMN2DUGUL`, bundle prefix `com.osborne.deadbolt` |
| Chrome | MV3 extension, **no build step, no dependencies** (like `../superform`). Stores no secrets. Talks to the Mac app via **native messaging** |
| Sync | **Option (b): Cloudflare Worker dead-drop.** Holds E2E-encrypted, signed ops only until every other device has fetched them, then deletes. Unclaimed ops deleted after **7 days**. Never a full vault. Behind a pluggable `SyncTransport` protocol |
| LAN sync | Not in v1 (relay works on any Wi-Fi). Maybe later as another `SyncTransport` |
| Account | Mullvad-style **16-digit account number**. It is an *address*, not a secret, and can't decrypt anything |
| Linking | New device gets the account number (QR scan from an existing device; typing is a fallback) → existing device shows "Link <device>? code 4-8-2-1" → owner compares codes on both screens and approves → vault key sent E2E. Deny by default |
| Unlock | **Master password** (Argon2id) **+ biometrics** (Face ID / Touch ID). Master password re-required periodically and after restart. Phone/Mac passcode is **not** accepted as fallback |
| Recovery | Printable **Recovery Kit**: 24 words (recovery key), account number, QR |
| Backups | Automatic **encrypted backup file** (weekly + after big changes) to an owner-chosen folder (iCloud Drive / USB / NAS), encrypted under the **recovery key**, not the master password |
| iCloud device backup | Vault DB **excluded** from iOS/macOS device backups (`isExcludedFromBackup`); backup file covers recovery |
| Crypto | CryptoKit (Swift), WebCrypto (JS), libsodium only for Argon2id. **No hand-rolled primitives** |
| Accounts per site | Many. An account is identified by **(site, username)**, username compared case-insensitively. Saving the same site+user **updates** (old password → history, max 20); same password → no prompt; "Save as a separate login" is the explicit escape hatch. One account per site is **preferred** (suggested first); first saved = preferred |
| Site matching | A saved site covers itself and its subdomains only (`gist.github.com` ⊂ `github.com`; `github.com.evil.example` never matches). Logic in `Core/.../Vault/LoginItem.swift` (`Site`) |
| Settings › About | Every app has About (sheet on iOS, window on Mac): version, project page link (**https://deadbolt.osborne.vc**), privacy link, open-source acknowledgements (CryptoKit, libsodium, BIP39 list) |
| Settings › Privacy | Every app has a Privacy screen: no account/login, encrypted before storage, sync without a server copy (≤7 days relay), no analytics, backups you control, and honestly **what the relay can see** (random mailbox ID, message sizes/times, IP) |
| Logo | Source `deadbolt-logo.png` (gold squircle, cream padlock + shield). Derived: iOS full-bleed 1024 (white corners replaced by a fitted gold gradient), Mac icon on the 824/1024 grid with transparency, in-app `Logo` (clipped in `DeadboltMark`), menu-bar `MenuBarIcon` template (padlock glyph only), website `logo.png`/`favicon.png`/`apple-touch-icon.png`. All in `Apps/Shared/Assets.xcassets` and `website/public/`. Regenerate from the source rather than editing derived files |
| UI design | Canvas: https://claude.ai/artifact/XaS4NKFZCvWkKNTgoifMDJ — "Graphite & Brass" (#0B0C0F ground, #D4AF6A accent, Geist + Geist Mono). UX rules: every tap gives progress + result; secrets masked by default; sync status always visible |

**Recovery rule:** access survives if the owner has *either* one working device + master password/biometrics, *or* a backup file + Recovery Kit.

### Learned from github.com/championswimmer/TwoFac
Borrow ideas, not code: browser↔desktop **companion mode** over native messaging; a **transport interface** so sync backends are swappable; biometric Keychain item (`biometryCurrentSet`, `WhenUnlockedThisDeviceOnly`) with a test proving secrets are really in the Keychain; shared session-retention policy ("ask every time" vs "until app/browser closes"); duress PIN (later); TOTP importers. **Do not copy its crypto** (PBKDF2 at 200 iterations).

## 2. Platform facts that shape the design

| Feature | iOS | Mac (Safari + apps) | Chrome on Mac |
|---|---|---|---|
| Autofill passwords | AutoFill Credential Provider extension | same (macOS) | our extension |
| Passkeys | credential provider passkey APIs | same | extension overrides `navigator.credentials` (MAIN world) → Mac app signs |
| Save new passwords | **iOS 26.2+: system save prompt via `ASSavePasswordRequest`** (Safari + apps; also `ASGeneratePasswordsRequest`). iOS 18–26.1: in-app only | Safari Web Extension (no save API on macOS) | extension save-on-submit |
| Chrome on iOS | uses the iOS credential provider | — | — |

Confirmed from the iOS 27.2 SDK headers (2026-11-18): `prepareInterface(for: ASSavePasswordRequest)` / `performWithoutUserInteractionIfPossible(savePasswordRequest:)` and capability key `SupportsSavePasswordCredentials` are iOS 26.2+, unavailable on macOS. Still to verify on device: that iOS actually routes save prompts to our provider, and passkey registration on iOS 18 and 26.

## 3. Architecture

```
┌──────────── iPhone ────────────┐        ┌──────────────── Mac ─────────────────┐
│ Deadbolt app (vault UI, sync)  │        │ Deadbolt menu-bar app (always on)    │
│ AutoFill provider ext ─┐       │        │ AutoFill provider ext ─┐             │
│ Safari web ext ────────┤       │        │ Safari web ext ────────┤             │
│        App Group: encrypted DB │        │  App Group: encrypted DB             │
└──────────────┬─────────────────┘        │ Native-messaging host ◄── Chrome ext │
               │                          └──────────────┬───────────────────────┘
               └──── Cloudflare Worker dead-drop (ciphertext only, ≤7 days) ─────┘
```

### Keys
- **VK (vault key):** random 256-bit, created on first device. Items sealed with AES-GCM (or ChaChaPoly) under HKDF-derived subkeys; each record carries a key ID / **epoch**.
- **At rest:** VK wrapped twice — by Argon2id(master password) and by a biometric Keychain item (shared access group so the AutoFill extension can unlock).
- **Device identity:** per-device P-256 signing key in the Secure Enclave. Every sync op is signed; peers accept only signatures from paired, non-revoked devices.
- **Recovery key:** 256-bit, shown as 24 words. Wraps VK and encrypts backup files.
- **Relay addressing:** relay room/mailbox ID derived from VK (unlinkable to the account number on the server side); devices authenticate to the Worker with signatures, Worker enforces quotas and rate-limits link requests.

### Sync model
- Every device holds a **full replica**.
- Changes are an op log with **per-field last-writer-wins on hybrid logical clocks**, tombstones for deletes, **password history** so a merge never loses a value.
- Ops carry per-device sequence numbers: replays deduped, gaps (withheld ops) detected.
- iOS: sync on app open, `BGAppRefreshTask`, and right after an extension saves. Mac menu-bar app stays connected.

### Passkeys
ES256 keys generated by us, stored in the vault (synced; BE/BS flags set; sign counter 0). rpId checked against the real origin using the Public Suffix List on the trusted side — never trust what the page claims.

### Chrome extension rules (carried from superform)
- Site comes from `sender.tab.url`, never from page content.
- Content scripts get a narrow API; values only on explicit user action, dropped after.
- Master password never typed into a web page.
- Fill only on exact site match, never into hidden or cross-origin frames.

## 4. Threat handling

| Event | Protection | Response |
|---|---|---|
| Phone/Mac stolen (locked) | Encrypted at rest; needs biometrics or master password; device passcode not enough | From another device: **Remove device** → revoke sync access, **rotate VK (new epoch)**, queued remote-wipe command, list of passwords to change |
| Stolen while unlocked | Short auto-lock, lock on screen lock/sleep, re-auth to reveal/copy | Same as above |
| New/replacement device | Link needs approval + code comparison on an existing device | Scan QR, approve, enter master password |
| Forgot master password | Biometric-unlocked device can set a new one (syncs) | Else Recovery Kit |
| Stranger has account number | Can't link without approval; notification per request; rate limits | Deny; rotate account number if repeated |
| Worker down or compromised | Ciphertext only; signed, sequenced ops | Devices work offline, catch up later |
| Concurrent offline edits | Per-field LWW + history | Nothing lost |
| Phishing / lookalike site | Exact-match fill; passkeys domain-bound | Won't offer to fill |
| Deadbolt bug corrupts vault | Append-only log, snapshots, backup files, versioned migrations | Restore; run Apple Passwords in parallel until v1 is proven |
| Malware on unlocked Mac | **Out of scope** — limit exposure only | Keep OS updated |

## 7. Working rules for agents

- Read this file first. Settled decisions in §1 stand unless the owner changes them; record any change here.
- Track each phase in `.agents/plans/NN-name.md` with `status:` and a `progress:` checklist; update as you go.
- Crypto: only CryptoKit / WebCrypto / libsodium. Every format has a version byte and AAD binding. Add test vectors for every crypto and encoding path.
- Never log, print or persist plaintext secrets, keys or passwords — including in tests' failure output and debug builds.
- Website: no third-party requests (no Google Fonts, analytics or CDNs) — its footer promises no tracking.
- Never send any personal data (owner's name, email, vault contents) to outside services.
- Keep dependencies minimal: libsodium for Argon2id is the only planned third-party dependency. Ask before adding another.
- Chrome extension: no build step, no npm runtime deps; tests may use Node.
- Regenerate the Xcode project with `xcodegen generate`; never commit hand edits to `.xcodeproj`.
- Shipping to TestFlight: use the `apple-distribution` skill.
